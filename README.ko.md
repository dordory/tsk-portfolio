# TSK — LINE 미니앱으로 만든 구역 관리 시스템

*[English README](README.md)*

회중의 봉사 **구역(territory)**을 관리하는 Django 웹 애플리케이션으로, **LINE MINI App(LIFF)** 형태로 배포됩니다. 사용자는 LINE 계정으로 로그인하고, 구역카드 데이터는 **구글시트**를 그대로 읽고 씁니다 — 스프레드시트가 데이터의 단일 원천(source of truth)으로 남고, 웹앱은 그 위에 인증과 모바일 UI를 얹습니다.

> 이 리포지토리는 비공개 작업 리포의 스냅샷을 포트폴리오 용도로 공개한 것입니다. 조직 실명과 자격증명은 모두 환경변수로 외부화되어 있습니다.

## 엔지니어링 포인트

**LINE 미니앱 인증을 서버 측에서 완결.**
LIFF 프론트는 부트스트랩만 담당합니다 — ID 토큰을 받아 서버로 POST하면, 서버가 LINE 검증 엔드포인트로 토큰을 검증(표준 라이브러리 `urllib`만 사용, SDK 무의존)하고 일반 Django 세션을 수립합니다. 온보딩은 관리자가 멤버별로 발급하는 **1회용 초대코드**로 LINE 계정을 사전 등록된 멤버에 연결하며, 이미 연결된 멤버는 재연결이 불가능해 계정 탈취를 방지합니다(`apps/line`).

**하이브리드 데이터 계층.**
사용자 신원은 DB(소프트 삭제를 지원하는 커스텀 `AUTH_USER_MODEL`)에 있지만, 구역카드 도메인 데이터는 **모델이 아예 없습니다** — 서비스 계정으로 구글시트를 직접 읽고 씁니다(`apps/territory_cards`). 회중은 익숙한 스프레드시트 운영 방식을 그대로 유지하고, 앱은 인증·모바일 UX·안전한 쓰기를 더합니다.

**시트 로직을 순수 함수로 격리.**
Sheets API 호출 없이 계산 가능한 모든 것 — 좌표 상수, 셀 파싱, 방문기록 조립, 상태→색 매핑, 데이터 끝 행 동적 탐지 — 은 Google import가 전혀 없는 `mapping.py`에 모여 있어 네트워크 없이 단위테스트가 가능합니다. Google 클라이언트 라이브러리는 함수 안에서 지연 import되어, 미설치 환경에서도 앱이 기동합니다.

**사람이 직접 편집하는 시트에 대한 안전한 쓰기.**
앱이 쓰는 시트를 사람들이 계속 직접 편집하므로, 모든 쓰기에 안전장치가 있습니다. 탭은 불변 ID(`gid`)로 식별해 이름변경·재배열에도 URL이 깨지지 않고, 행 단위 쓰기에는 **행 지문**(주소 열)을 실어 서버가 쓰기 직전에 시트를 다시 읽어 대조합니다 — 불일치면 409를 돌려주고 UI가 새로 읽은 목록으로 유도해, 그 사이 행이 삽입됐어도 방문기록이 엉뚱한 집에 기록되지 않습니다. 쓰기는 `RAW` 입력(자유 입력 메모를 통한 수식 주입 차단)입니다. 캐시는 2단 구조 — 잘 안 바뀌는 메타데이터(마스터 인덱스·탭 목록·상태값)는 5분, 구역 본문은 60초에 본인 쓰기 직후 무효화 — 로 화면당 API 왕복을 3~4회에서 0~1회로 줄이되, 쓰기 직전의 검증 읽기는 항상 캐시를 우회합니다(정합성 경로).

**메신저 중립 코어를 가진 그룹채팅 봇.**
공식계정 봇이 회중 그룹채팅의 키워드에 답합니다(친구 추가 불필요) — 리치 Flex 메뉴, *보낸 사람의* 다음 성경 읽기 부분, 오늘의 성구, 그리고 wol.jw.org에서 실시간 추출한 이번 주 성서 읽기 범위(성공 시 캐시, 실패 시 명시적 폴백 — 침묵 금지)까지. 동작 결정 로직은 정규화된 `(텍스트, 보낸이)`를 받아 **추상 응답 객체(데이터만)**를 돌려주는 플레인 패키지 `apps/bot`에 있고, `apps/line`은 어댑터일 뿐입니다 — 웹훅 서명 검증과 Flex 렌더러, 둘 다 표준 라이브러리 `urllib`만 사용. 다른 메신저 이식은 어댑터 하나를 새로 쓰는 일이 됩니다. 키워드와 메뉴 타일은 admin에서 관리하는 DB 행이라, 배포 없이 봇의 어휘를 바꿀 수 있습니다.

**아이들을 위한 성구 스탬프 체크(그룹채팅 속 용돈 시스템).**
아이가 그룹채팅에 "\<성구\> 읽음"을 보내면, 봇이 문장을 파싱하고 wol.jw.org에서 그날의 실제 성구를 가져와 책+장을 대조한 뒤에 도장을 찍습니다 — 불일치는 *정답을 알려주지 않고* 부드럽게 반려합니다(정직 교육 취지). 인정된 체크(하루 1회, 소급은 어제까지)는 달력형 Flex 스탬프 카드, 연속 일수·마일스톤 피드백, 아이별 단가와 개근 보너스가 있는 월말 정산으로 이어집니다. 과거 이력 보정은 관리자가 탭해서 토글하는 달력 화면에서 합니다.

**웹/LIFF 이중 렌더링.**
미들웨어가 LIFF 세션을 플래그(`request.is_liff`)하고, 템플릿 해석 헬퍼가 `liff/<name>` 템플릿이 있으면 우선 사용하고 없으면 원본으로 폴백합니다. 하나의 뷰가 인앱 WebView와 일반 브라우저를 모두 서비스합니다.

**실전 배포 함정 해결.**
PythonAnywhere의 필수 아웃바운드 프록시 환경에서 동작합니다 — PySocks가 없으면 `httplib2`가 프록시 설정을 *조용히 무시*하는 미묘한 실패까지 포함해서요(해결책은 `requirements.txt`와 `sheets.py`의 명시적 프록시 주입에 코드화되어 있습니다).

## 기술 스택

Python 3.11 · Django 5.2 · google-api-python-client (서비스 계정) · LIFF v2 · Tailwind (CDN) · SQLite

## 실행 방법

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # 값 채우기 (둘러보기만 할 땐 전부 비워도 됨)
python manage.py migrate
python manage.py runserver
```

LINE/Google 변수를 비워두고 `DEBUG=True`면 **개발용 우회 로그인 모드**(멤버 직접 선택)로 동작해, 외부 계정 없이도 UI를 둘러볼 수 있습니다.

### 주요 환경변수

| 변수 | 용도 |
|------|------|
| `SECRET_KEY` | Django 시크릿. 미설정 시 프로세스마다 랜덤 생성(개발 전용) |
| `CONGREGATION_NAME` | 화면에 표시할 조직 이름 (소스에 하드코딩하지 않음) |
| `LINE_LIFF_ID`, `LINE_CHANNEL_ID` | LINE MINI App 자격증명. 비우면 LINE 로그인 비활성 |
| `LINE_MESSAGING_CHANNEL_SECRET`, `LINE_MESSAGING_ACCESS_TOKEN` | Messaging API 채널(공식계정 봇). 비우면 웹훅 비활성 |
| `GOOGLE_SERVICE_ACCOUNT_FILE` / `_JSON` | Sheets/Drive 접근용 서비스 계정 키 |
| `TERRITORY_CARDS_MASTER_SHEET_ID` | 구역카드 마스터 인덱스 시트 ID |

## 참고

- UI 텍스트는 한국어이며(도쿄의 한국어 회중 대상), 타임존은 `Asia/Tokyo`입니다.
- 테스트(269건)는 순수 시트 매핑 로직, LINE 토큰 검증(목킹), 쓰기 안전장치, 캐시·무효화, 봇 키워드 라우팅, 성구 파싱·정산 계산, 템플릿 렌더링을 커버합니다: `python manage.py test`
- 퀴즈 앱에는 직접 생성한 **샘플 카드**가 들어 있습니다. 실제 카드 이미지는 저작물이라 이 공개 스냅샷에서 제외했습니다.
